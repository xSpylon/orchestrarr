# Orchestrarr governance

Orchestrarr is an open community project with one canonical upstream:
<https://github.com/xSpylon/orchestrarr>. The official project site is
<https://orchestrarr.com>.

## Maintainers

Maintainers protect the project's purpose, review changes, publish releases,
handle security reports and keep the official distribution trustworthy. The
repository owner may add or remove maintainers as the project grows.

Maintainers should prefer small, reviewable changes, explain decisions in
issues or pull requests, and keep the roadmap visible. A maintainer's role is
to serve the project and its users, not to claim ownership of contributors'
work.

## Decision making

Routine fixes can be merged by a maintainer after review. Changes to the
public API, license, project identity, data handling, security model or
supported deployment model should be discussed in an issue or design note
before implementation.

The project uses the default branch as its integration branch. Releases are
cut from reviewed commits that pass the repository checks. Release notes name
contributors and link to the relevant pull requests where practical.

## Contributions and forks

Contributions are accepted under the [AGPL-3.0 license](LICENSE) and must
follow [CONTRIBUTING.md](CONTRIBUTING.md), including the Developer Certificate
of Origin sign-off. Contributors keep their copyright in their work while
granting the project the rights needed to distribute it under the project
license.

Forks are welcome. The [trademark policy](TRADEMARKS.md) keeps the official
project identity clear, and upstream contributions are encouraged to reduce
fragmentation and give contributors visible recognition.

## Security

Do not disclose vulnerabilities in public issues. Follow [SECURITY.md](SECURITY.md)
for private reporting and deployment boundaries.
